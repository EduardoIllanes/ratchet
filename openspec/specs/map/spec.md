# map

Deterministic, on-demand repo orientation, cached at `.ratchet/map.md` for every session and
subagent to load through one `CLAUDE.md` import.

## Purpose

A session or subagent that has never seen a repo pays for orientation by reading directories and
READMEs itself, every time. `ratchet map` derives that orientation deterministically from `git
ls-files`, file headers and manifest files, with no model involved; a separate pass fills in the
files a header cannot describe. The map is local, untracked, and regenerated only on request; a
session-start line says only when it is stale.

## Requirements

### Requirement: Generation is deterministic
`ratchet map` SHALL derive the whole map from `git ls-files`, file heads and manifest contents,
with no model invoked by the binary. Two runs over the same tree, with no note, commit or config
change between them, SHALL produce byte-identical output.

#### Scenario: Two runs are byte-identical
- **WHEN** `ratchet map` runs twice in succession over the same tree, with nothing changed
  between the runs
- **THEN** the two writes of `.ratchet/map.md` are byte-identical

### Requirement: Map generation writes fixed, ordered sections
`ratchet map` SHALL write `.ratchet/map.md` with, in order: a Header (`# <repo> — map` then
`generated by ratchet map at <sha> (<date>); do not edit, run /ratchet:map`); a Gate, one command
per line, either `[map] gate` verbatim or detected from manifests (`Cargo.toml` → `cargo fmt
--all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`; `pyproject.toml` or
`pytest.ini` → `pytest` or `uv run pytest` when `uv.lock` exists, plus `ruff check` and `mypy`
when configured; `package.json` → its `test`, `lint` and `typecheck` scripts via the lockfile's
package manager; `Makefile` → `make test` and `make lint` when those targets exist; `go.mod` →
`go test ./...` and `go vet ./...`); a Layout of top-level directories, and one level down for
marked source directories, each with file count, common extensions and named entry points; a
Modules line per source file (`path — sentence`); a Tests section of test directories and
counts; a Docs section for `README*`, `CLAUDE.md`, `AGENTS.md`, `docs/` and `openspec/specs`,
with counts and capability names; and a Footer with header/note/neither counts, ending
`<!-- ratchet-map commit=<sha> tree=<hash> -->`. An empty section SHALL be omitted. On success
`ratchet map` SHALL print `wrote .ratchet/map.md (<lines> lines, <k> modules without a
description)`. Outside a repository with a `ratchet.toml` marker, or when `git ls-files` fails,
it SHALL exit 1 and write no file.

#### Scenario: A repo with every section present
- **WHEN** `ratchet map` runs in a repo with a `Cargo.toml`, a `src/lib.rs` with a `//!` header,
  a `tests/` directory, a `README.md` and an `openspec/specs/pdf/spec.md`
- **THEN** stdout is `wrote .ratchet/map.md (<n> lines, 0 modules without a description)`;
  `.ratchet/map.md` has Header, Gate, Layout, Modules, Tests, Docs and Footer in that order, each
  once; the Gate section is exactly `cargo fmt --all -- --check`, `cargo clippy --all-targets --
  -D warnings` and `cargo test`; and its last line is `<!-- ratchet-map commit=<sha> tree=<hash>
  -->`

#### Scenario: Empty sections are omitted
- **WHEN** `ratchet map` runs in a repo with source files but no test directory, no test files,
  and none of `README*`, `CLAUDE.md`, `AGENTS.md`, `docs/` or `openspec/`
- **THEN** `.ratchet/map.md` has no `Tests` heading and no `Docs` heading, and the remaining
  sections keep their relative order

#### Scenario: No marker, no map written
- **WHEN** `ratchet map` runs in a git repository with no `ratchet.toml` at its root
- **THEN** it exits 1, stderr names the missing marker, and no `.ratchet/` directory is created

### Requirement: Module descriptions come from the file's own header
Each source file SHALL get one Modules line, `path — sentence`. The sentence SHALL be the file's
header comment, cut at the first sentence and 120 characters: Rust's leading `//!` block, a
Python module docstring, or TypeScript's leading `/** … */` or `//` block. Without a header, the
sentence SHALL be the stored note for that path; without either, `—`.

#### Scenario: Header extracted per language, dash when there is neither
- **WHEN** `ratchet map` runs in a repo with `src/lib.rs` starting `//! Parses the manifest.
  Nothing else.`, `scripts/build.py` starting `"""Builds the release archive."""`,
  `web/index.ts` starting `// Boots the dev server.`, and `scripts/plain.py` with no header
  comment and no entry in `.ratchet/map.notes`
- **THEN** the Modules lines read `src/lib.rs — Parses the manifest.`, `scripts/build.py —
  Builds the release archive.`, `web/index.ts — Boots the dev server.` and `scripts/plain.py —
  —`

### Requirement: Notes fill gaps but never outrank a header
`.ratchet/map.notes` entries SHALL be merged into the Modules section at generation. A file's own
header comment SHALL always be used over a note for the same path. A note whose path is no
longer a tracked file SHALL be dropped from `.ratchet/map.notes` at the next generation.

#### Scenario: A note is used, then loses to a later header
- **WHEN** `ratchet map note scripts/util.py "Rotates logs."` runs and `ratchet map` regenerates,
  and `scripts/util.py` is then given a header comment and `ratchet map` regenerates again
- **THEN** the first map's Modules line for `scripts/util.py` uses the note's sentence, and the
  second map's line uses the header's sentence instead

#### Scenario: A stale note is dropped
- **WHEN** the file a note describes is deleted from the repo and committed, and `ratchet map`
  regenerates
- **THEN** `.ratchet/map.notes` no longer contains a line for that path

### Requirement: The map never exceeds 150 lines
`.ratchet/map.md` SHALL be at most 150 lines. Over the cap, module lists SHALL collapse into one
line per directory carrying its file count, deepest directories first, until the map fits. The
Header, Gate and Footer sections SHALL never collapse.

#### Scenario: A large module list collapses by directory
- **WHEN** `ratchet map` runs in a repo whose `src/deep/` subdirectory alone has enough source
  files to push the map past 150 lines
- **THEN** `.ratchet/map.md` is at most 150 lines, `src/deep/` appears as one line with its file
  count instead of one line per file, and the Header, Gate and Footer sections are unchanged

### Requirement: Wiring the map into `CLAUDE.md` and `.gitignore`
`ratchet map --wire` SHALL append `.ratchet/` to `.gitignore` (creating it if absent) and append
a block with the import line `@.ratchet/map.md` to `CLAUDE.md` (creating it if absent); a second
run SHALL change neither file and SHALL say so. When either file exists but is not a regular
file, `--wire` SHALL write the map, name the offending file on stderr, and exit 1 without
touching either file. Plain `ratchet map` SHALL print one hint line per missing wire, naming
`--wire`.

#### Scenario: Wiring is idempotent
- **WHEN** `ratchet map --wire` runs twice in a repo with neither `CLAUDE.md` nor `.gitignore`
- **THEN** after the first run `.gitignore` contains `.ratchet/` and `CLAUDE.md` contains
  `@.ratchet/map.md`; the second run leaves both files byte-identical and stdout says nothing
  changed

#### Scenario: A symlinked CLAUDE.md is refused
- **WHEN** `ratchet map --wire` runs in a repo where `CLAUDE.md` is a symlink
- **THEN** it exits 1, stderr names `CLAUDE.md`, `.ratchet/map.md` is written, and the symlink is
  untouched

### Requirement: `--missing` lists undescribed source files
`ratchet map --missing` SHALL print, one path per line, the source files with neither a header
nor a note. With a map already present, it SHALL list only those changed since the map's
recorded commit; `--all` SHALL widen the list back to every undescribed source file. It SHALL
print nothing and exit 0 when the list is empty.

#### Scenario: First pass lists every undescribed file
- **WHEN** `ratchet map --missing` runs before any map has been generated, in a repo with three
  header-less, note-less source files
- **THEN** stdout has exactly those three paths, one per line, and exit code is 0

#### Scenario: A later pass is incremental, `--all` widens it back
- **WHEN** a map is generated, one new header-less file is added and committed, and `ratchet map
  --missing` runs, followed by `ratchet map --missing --all`
- **THEN** the first call's stdout has only the new file; the second call's stdout lists every
  undescribed file, old and new

### Requirement: `map note` validates before recording
`ratchet map note <path> "<sentence>"` SHALL refuse, with exit 1 and one stderr line, a path
that is not a tracked file or a sentence that is empty, contains a newline, or exceeds 120
characters. A valid call SHALL replace any existing note for the same path and SHALL NOT
regenerate the map.

#### Scenario: A valid note replaces the prior one
- **WHEN** `ratchet map note scripts/util.py "Rotates logs."` runs, then `ratchet map note
  scripts/util.py "Rotates and compresses logs."` runs
- **THEN** `.ratchet/map.notes` holds one line for `scripts/util.py`, with the second sentence,
  and `.ratchet/map.md` is untouched by either call

#### Scenario: Invalid notes are refused
- **WHEN** `ratchet map note not/a/real/file.py "Does something."` runs, and separately
  `ratchet map note scripts/util.py "<a 121-character sentence>"` runs
- **THEN** each exits 1 with one stderr line, and `.ratchet/map.notes` is unchanged by either
  call

### Requirement: A status line reports whether the map is current
Both `ratchet map status` and the session-start briefing, in a marker repo, SHALL print the same
line: `map: none — run /ratchet:map for the repo layout` when no map exists; `map: <n> commits
behind — run /ratchet:map` when the recorded commit is an ancestor of `HEAD` but not `HEAD`
itself (`<n>` = `git rev-list --count <recorded>..HEAD`); `map: from another branch — run
/ratchet:map` when the recorded commit is not an ancestor of `HEAD`; or, when current, `map:
current` for `status` and nothing for the briefing. `status` SHALL exit 0 in every case.

#### Scenario: No map yet
- **WHEN** `ratchet map status` runs, and separately a session starts, in an opted-in repo with
  no `.ratchet/map.md`
- **THEN** both print `map: none — run /ratchet:map for the repo layout`

#### Scenario: Map behind by commits
- **WHEN** a map is generated, three more commits are made, and `ratchet map status` runs
- **THEN** stdout is `map: 3 commits behind — run /ratchet:map`

#### Scenario: Map recorded on another branch
- **WHEN** a map is generated on one branch, and `ratchet map status` runs after checking out a
  diverged branch whose history does not contain the recorded commit
- **THEN** stdout is `map: from another branch — run /ratchet:map`

#### Scenario: Current map
- **WHEN** `ratchet map status` runs, and separately a session starts, right after `ratchet map`
  with no commits since
- **THEN** `status` prints exactly `map: current`, and the briefing carries no `map:` line

### Requirement: `[map]` config excludes paths and can replace the gate
`ratchet.toml`'s `[map]` section SHALL support `exclude` (directory globs left out of Layout,
Modules and Tests entirely) and `gate` (commands that replace gate detection entirely), both
defaulting to empty.

#### Scenario: `exclude` removes a directory from the map
- **WHEN** `ratchet map` runs with `[map] exclude = ["vendor/**"]` in `ratchet.toml` and the repo
  has tracked source files under `vendor/`
- **THEN** no `vendor/` file appears in the Layout, Modules or Tests sections

#### Scenario: `gate` replaces detected commands
- **WHEN** `ratchet map` runs in a Cargo repo with `[map] gate = ["just check"]` in
  `ratchet.toml`
- **THEN** the Gate section is exactly `just check`, and no `cargo` command appears
