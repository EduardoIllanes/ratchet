# ratchet map — repo orientation without re-reading the repo

Date: 2026-09-21. Owner: Eduardo Illanes. Status: design, awaiting owner review. Extends the
plugin design (`2026-09-16-ratchet-plugin-design.md`) with a task group 6.

## 1. Purpose

Every session, and every subagent, starts by re-learning where things are: the tree, the
entry points, the tests, the gate. That costs a README and a few directory listings per
session, and in a repo without a maintained `CLAUDE.md` it costs it every time. A hand-written
map fixes this for one repo and rots in every other, because nobody remembers to update it.

`ratchet map` derives the map from the repository itself, deterministically, on demand. A
model touches it only where the tree has no answer (a module with no header comment), and only
for the files that changed since the last time. Claude Code loads the result into every
session and subagent through one `CLAUDE.md` import. The session-start briefing says when the
map is behind; it never regenerates anything on its own.

Not in scope: symbol indexes, call graphs, semantic search, anything that needs a parser per
language. Regenerating on every session start (owner decision, 2026-09-21: on demand only).

## 2. Decisions

- **D-map-deterministic.** The binary produces the whole map from `git ls-files`, file headers
  and manifest files. Two runs on the same tree produce byte-identical output. No model is
  involved in the binary.
- **D-map-on-demand.** The map is generated by `/ratchet:map` (or `ratchet map`) when the user
  asks. Session start only compares the stored commit with `HEAD` and prints one line if they
  differ. Rationale: cost is paid when the user wants a fresh map, not per session.
- **D-map-notes.** Descriptions a model writes for header-less modules live in
  `.ratchet/map.notes`, one `path: sentence` per line, written only through `ratchet map note`.
  The map merges them at generation. A header comment in the file always wins over a note. Notes
  for files that no longer exist are dropped at the next generation.
- **D-map-haiku.** The deep pass is a `mapper` agent on `haiku`, `effort: low`, tools `Read,
  Grep, Glob, Bash`. It reads the first 40 lines and the public signatures of each file it is
  given, never whole files, and records one sentence per file through the binary. It edits no
  other file.
- **D-map-incremental.** `ratchet map --missing` lists the source files that have no header
  and no note. After a first deep pass, a later one only gets files changed since the commit
  recorded in the map (`git diff --name-only <recorded>..HEAD`, intersected with the missing
  list). The second deep pass costs a fraction of the first.
- **D-map-untracked.** `.ratchet/map.md` and `.ratchet/map.notes` are local, untracked
  files. Each clone generates its own. `ratchet map` never writes a tracked file; wiring
  `CLAUDE.md` and `.gitignore` is a separate, explicit `--wire`, run once, and the command
  `/ratchet:map` asks the user before running it. Rationale: the `main-tree` guardrail doctrine
  (no tracked-file writes from a session unless the owner asked) applies to the binary too.
- **D-map-cap.** A map is at most 150 lines. Over the cap, module lists collapse into their
  directory (one line with a file count), deepest directories first, until it fits. A map is
  context in every prompt; it is never allowed to grow with the repo.
- **D-map-config.** `ratchet.toml` gains an optional `[map]` section: `exclude` (directory
  globs left out entirely) and `gate` (commands that replace detection). Both default to empty.

## 3. The map

Written to `<repo root>/.ratchet/map.md`, in this order. Every section is omitted when empty.

1. **Header.** `# <repo name> — map`, then one line: `generated by ratchet map at <commit
   short sha> (<date>); do not edit, run /ratchet:map`.
2. **Gate.** The commands that make the repo green, one per line. Detected from manifests
   (`Cargo.toml` → `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`,
   `cargo test`; `pyproject.toml` or `pytest.ini` → `pytest` or `uv run pytest` when
   `uv.lock` exists, plus `ruff check` and `mypy` when configured; `package.json` → the
   `test`, `lint` and `typecheck` scripts that exist, via the lockfile's package manager;
   `Makefile` → `make test` and `make lint` when those targets exist; `go.mod` → `go test
   ./...`, `go vet ./...`). `[map] gate` in `ratchet.toml` replaces detection entirely.
3. **Layout.** Every top-level directory with its tracked file count and the two most common
   extensions, one line each; the same one level down for directories the manifest marks as
   source (`src`, `crates/*`, `lib`, `app`, `cmd`, `pkg`, `packages/*`). Entry points named
   in their own line: `main.rs`, `lib.rs`, `__main__.py`, `main.py`, `index.ts`, `index.js`,
   `main.go`, `bin/*`.
4. **Modules.** One line per source file, `path — sentence`. The sentence is the file's
   header comment when it has one (`//!` in Rust; a module docstring in Python; the leading
   `/** … */` or `//` block in TS, JS, Go, Java, Kotlin, Swift, C and C++; `#` comment block
   after the shebang in shell), cut at the first sentence and 120 characters; else the note
   from `map.notes`; else `—`. Source files are those under the layout's source directories
   plus any file whose extension is in the language table. Files matched by `[map] exclude`,
   and vendored or generated trees (`node_modules`, `target`, `dist`, `build`, `vendor`,
   `.worktrees`, anything gitignored) never appear; `git ls-files` already hides the latter.
5. **Tests.** Test directories and their file counts, and test files living beside source
   (`*_test.go`, `test_*.py`, `*.test.ts`) as one count per directory.
6. **Docs.** `README*`, `CLAUDE.md`, `AGENTS.md`, `docs/`, `openspec/`, `specs/`: presence,
   file counts, and for `openspec/specs` the capability names.
7. **Footer.** `<n> files with a header, <m> with a note, <k> without either — run
   /ratchet:map --deep for the rest.` The tree hash and the commit sha, machine-readable, on
   the last line (`<!-- ratchet-map commit=<sha> tree=<hash> -->`).

Cap: D-map-cap. Sections 1, 2, 7 never collapse.

## 4. Components

### 4.1 `ratchet map` (binary)

- `ratchet map` — generate the map and write it. Prints `wrote .ratchet/map.md (<lines> lines,
  <k> modules without a description)`. When `CLAUDE.md` does not import the map, or
  `.gitignore` does not cover `.ratchet/`, adds one hint line per missing wire, naming
  `--wire`. Exit 1 outside a repo with a marker, or when `git ls-files` fails.
- `ratchet map --wire` — additionally: appends `.ratchet/` to `.gitignore` (creating it) and
  appends a short block to `CLAUDE.md` (creating it) with the import line
  `@.ratchet/map.md` and a two-line comment saying what it is and how to refresh it. Idempotent:
  a second run changes nothing and says so. Never rewrites what is already in either file.
- `ratchet map --missing` — print the source files that have neither header nor note, one path
  per line, relative to the root. With a map present, only those changed since the map's
  recorded commit (D-map-incremental); `--all` widens back to every such file. Prints nothing
  and exits 0 when the list is empty.
- `ratchet map note <path> "<sentence>"` — record one description. Refuses (exit 1, one
  stderr line) a path that is not a tracked file, a sentence over 120 characters or with a
  newline, or an empty sentence. Replaces an existing note for the same path. Does not
  regenerate the map.
- `ratchet map status` — one line, the same one the briefing prints (§4.3), or `map: current`;
  exit 0 always, and nothing printed outside a marker repo.

Implementation lives in a new `map` module (pure: takes the file list, file heads and manifest
contents, returns the map text) and a thin `cli/map_cmd.rs` face. Git is reached through the
same shell-out pattern as `repo::git_branch`. The file head read is capped at 4 KB per file.

### 4.2 `/ratchet:map` command and `mapper` agent

- `commands/map.md`: runs `ratchet map` through the hook wrapper. Reports the `wrote` line. If
  hint lines came back, shows them and asks the user before running `--wire`; runs it on a
  yes. With `--deep`: runs `ratchet map --missing`; when the list is non-empty, dispatches the
  `mapper` agent with that list (batches of at most 40 files per dispatch, sequential), then
  runs `ratchet map` again and reports the new footer counts. Never dispatches when the list
  is empty.
- `agents/mapper.md`: `model: haiku`, `effort: low`, `tools: Read, Grep, Glob, Bash`,
  `maxTurns: 120` (three per file of a 40-file batch). For each file: read the first 40 lines, grep its public
  signatures, write one sentence saying what the file is for (not what it contains), record it
  with `ratchet map note`. No other command, no other file, no report beyond the count
  recorded and any file it could not describe.

### 4.3 Briefing line

Session start (`hooks::briefing`) appends one line when a marker repo has:

- no map: `map: none — run /ratchet:map for the repo layout`;
- a map whose recorded commit is not `HEAD`: `map: <n> commits behind — run /ratchet:map`,
  where `<n>` is `git rev-list --count <recorded>..HEAD`; when the recorded commit is not an
  ancestor (rebase, other branch) the line says `map: from another branch — run /ratchet:map`.

Nothing is printed when the map is current. The 40-line cap of the briefing still holds; this
line counts against it and is dropped first when the cap is hit. The check is one `git
rev-parse` and, when different, one `git rev-list`; both under the SessionStart budget.

### 4.4 This repository

After group 6 ships, this repo runs `ratchet map --wire` once. Its `CLAUDE.md` is the import
line plus a hand-written block under 15 lines: the gate, the three layering rules that live in
module headers today (only `services/` writes the database; every mutation is an appended
event; CLI faces carry no SQL), and the versioning rule (`plugin.json` has no version; the
binary is pinned in `.claude-plugin/binary-version`; a release is a tag plus a `Cargo.toml`
bump). No paths in the hand-written block, so nothing there can rot.

## 5. Data flow

```
/ratchet:map ──> ratchet map ──> git ls-files, file heads, manifests, .ratchet/map.notes
                                   └──> .ratchet/map.md  (imported by CLAUDE.md into every prompt)
/ratchet:map --deep ──> ratchet map --missing ──> mapper (haiku) ──> ratchet map note ×N
                                                                    └──> ratchet map
SessionStart ──> briefing ──> map status line (read-only)
```

## 6. Error handling

- Anything git-related failing makes `ratchet map` exit 1 with one stderr line; the briefing
  line is skipped silently (a briefing never costs a session).
- A file head that is not UTF-8 is treated as having no header.
- `--wire` refuses to touch `CLAUDE.md` or `.gitignore` when either is not a regular file
  (symlink, directory); it says which and exits 1 after writing the map.
- `map note` validation as in §4.1. A note whose file later disappears is dropped, not an
  error.
- The `mapper` agent hitting `maxTurns` is not an error: the next `--deep` picks up the rest,
  because undescribed files stay in `--missing`.

## 7. Testing

- **Scenario tests** in `crates/ratchet/tests/spec/map.rs`, one per scenario of a new
  `openspec/specs/map/spec.md`, driving the binary over a temporary git repo with a marker and
  fixture files in Rust, Python and TypeScript: determinism (two runs, identical bytes); header
  extraction per language; note precedence and stale-note dropping; `--missing` full and
  incremental; `note` refusals; the 150-line collapse; `--wire` idempotence and refusal on a
  symlinked `CLAUDE.md`; the three briefing lines and their absence when current; `[map]
  exclude` and `gate` overrides.
- **Unit tests** in the `map` module for gate detection per manifest and the collapse order.
- No test involves a model. There is no agent frontmatter test today; group 6 adds one that
  parses every `agents/*.md` frontmatter and checks `name`, `model` and, where present,
  `effort` against the allowed values.
- Gate unchanged: `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`,
  scenario coverage.
